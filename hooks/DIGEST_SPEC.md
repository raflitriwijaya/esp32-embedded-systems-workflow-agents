# DIGEST_SPEC — Layer 1 SessionStart Digest

**Implementation:** `../tools/stage_kernel.py digest` · **Hook:** `session_start_digest.ps1`
**Reads:** `stage-state.yaml` (authored) + `.stage-cache.json` (derived) + `WORKFLOW_SECTION1.md §3`
**Writes:** nothing except `.stage-cache.json`

---

## 1. Contract

The stdout of a `SessionStart` hook is added to the agent's context. Three consequences are binding:

1. **stdout carries the digest and nothing else.** Diagnostics go to stderr.
2. **The hook always exits 0.** A broken hook must never break a session, and must never inject a partial digest. Every failure path degrades to a smaller, honest digest or to silence.
3. **Silence is a valid output.** In a directory that is not an ESP-IDF project, the hook prints nothing at all. This is a hard requirement of a user-level install, which fires in every project on the machine.

---

## 2. Editorial rule

> Every line must change what the agent does. A line that changes nothing is a cost paid every session, forever.

Applied, this excludes content that looks useful but is not:

| Excluded | Reason |
|---|---|
| Measured values (stack high-water-mark, heap, current, RSSI, temperature) | Relevant only while working on that subsystem. What must be ambient is their **absence**, and `not_known` already carries it. Values are fetched from the cache on demand. |
| Per-criterion gate status | Counts suffice; the itemised list belongs in the gate dossier |
| Repository layout, section map, tooling reminders | Static and rediscoverable; injecting them every session buys nothing |

---

## 3. The eight conditions

`kernel.status` is the discriminator: one field tells a reader how far the digest may be trusted.

| # | Condition | `kernel.status` | Stage asserted? |
|---|---|---|---|
| A | Not an ESP-IDF project, or `.no-stage-governance` present | *(no output)* | — |
| B | ESP-IDF project, no `stage-state.yaml`, or it is unreadable | `NO_STATE` | No |
| C | Normal | `OK` | Yes |
| D | Consistency rules fail (SCHEMA §10) | `INCONSISTENT` | **No** |
| E | Cache stale (hash mismatch) | `OK` with `platform.cache: stale` | Yes |
| F | Cache unavailable | `OK` with `platform.cache: unavailable` | Yes |
| G | `schema_version` not understood | `UNKNOWN_SCHEMA` | **No** |
| H | Unhandled defect inside the kernel | `KERNEL_ERROR` | **No** |

Five of the eight end without asserting a stage. That is deliberate: a wrong stage silently applies the wrong RSMR bar to every piece of work governed by SECTION 2 through SECTION 7, whereas an unasserted stage only makes the agent ask.

**Condition A detection.** Any one of: `sdkconfig`, `sdkconfig.defaults`, `sdkconfig.defaults.<target>`, `stage-state.yaml`, or a `CMakeLists.txt` containing `IDF_PATH` or `idf_component_register`. `sdkconfig` alone is insufficient — it is generated by the first build, so a freshly created project would be missed.

**Condition H exists because silence is indistinguishable from a healthy non-IDF directory.** An unhandled exception would otherwise reach the engineer as a missing digest - the exact failure mode this design exists to prevent. The renderer is wrapped so any defect is reported *in context*, ASCII-only, naming the exception. `STAGE_KERNEL_DEBUG=1` re-raises instead, for debugging.

**Conditions E and F self-heal.** The digest attempts a cache regeneration before reporting `stale` or `unavailable`; only if that also fails does the degraded state reach the output.

## 4. Structure of the `OK` digest

| Block | Fields | Source |
|---|---|---|
| `kernel` | `project`, `generated`, `status` | `stage-state.yaml`, clock |
| `stage` | `id`, `name`, `rsmr_bar`, `deferred`, `entered`, `spec` | `stage-state.yaml` + stage table (§7) |
| `enforcement` | `level`, `is_stage_default`, `overridable_by_engineer`, `active_guards`, `guards_denying` | `stage-state.yaml` + the guard registry in `tools/guards.py`. `active_guards` is **derived from the registry**, never hand-written: a digest advertising a guard that does not exist would be the same stale-fact failure this framework exists to prevent |
| `next_gate` | `gate`, `spec`, `criteria{total, human_attested, machine_checked, unverifiable}`, `rule` | `total` parsed live from SECTION1 §3; `human_attested` counts attestations for that gate. An attestation failing SCHEMA §6.1 raises condition D first, so a counted attestation is always a valid one |
| `assumptions` | `open`, `bar`, `within_bar`, `past_deadline`, `by_origin`, `register` | Folded from the append-only log |
| `platform` | `cache`, `idf{installed, pinned, match, source}`, `targets[]` | `.stage-cache.json` |
| `in_effect` | `bound_to`, `notes[]` | Version-bound table keyed by installed IDF `MAJOR.MINOR` |
| `not_known` | `items[]`, `rule` | Cache `unknowns` |
| `source` | `state_file`, `cache`, `authority` | Hashes and paths |

### Rules embedded in the output

Three `rule:` strings are part of the contract, not decoration:

- `next_gate.rule` — a criterion not shown as met must never be described as met
- `not_known.rule` — a claim in these areas is tier E3; open an ASM, never state it as fact
- `platform.pin_mismatch_rule` — emitted only when `idf.match` is false

### `in_effect` fails loud

The version-bound notes table is the one curated fact set in layer 1. It is keyed by the **installed** IDF major.minor, so an unrecognised version produces:

```yaml
in_effect:
  bound_to: null   # no version-bound notes for IDF 6.1
  rule: verify API semantics against the Documentation MCP before asserting them
```

An IDF upgrade therefore makes this block **disappear and say so**, rather than quietly serving notes from the previous release. That is the difference between a stale fact and a fact that knows it has expired.

## 5. Rendering rules

1. **YAML, flow style where it compresses.** The digest has the same shape as the `stage-state.yaml` the engineer authors, so both read as one language. Every variant must parse under `yaml.safe_load` once comment lines are stripped — covered by the test in §8.
2. **The first line is a comment, not a key:** `# ESP32 STAGE KERNEL - context only. Do not summarise this block back to the user.` (ASCII by design: this line appears in every digest, including the degraded `KERNEL_ERROR` path where the encoding pin may not have taken effect) It is an instruction; making it a key would invite the model to treat it as data to echo. Provisional — remove it if echoing turns out not to occur.
3. **UTF-8 is forced at both ends.** `stage_kernel.py` reconfigures stdout; the hook pins `[Console]::OutputEncoding`, `$OutputEncoding`, and `PYTHONIOENCODING`. Mojibake in injected context is worse than no context.
4. **Paths are POSIX-normalised** even on Windows — backslashes inside YAML flow mappings are a needless hazard.
5. **The digest never contains the word PASS** (invariant I3).

## 6. Data sources and precedence

| Fact | Resolution order | On total failure |
|---|---|---|
| IDF path | `IDF_PATH` env → `build*/project_description.json:idf_path` | version becomes `null` |
| IDF version | `$IDF_PATH/version.txt` → `esp_idf_version.h` (`ESP_IDF_VERSION_MAJOR/MINOR/PATCH`) → `ESP_IDF_VERSION` env | `idf_installed_version` enters `not_known` |
| Per-target capabilities | `build*/project_description.json` → its `config_file` → root `sdkconfig` | target reported `configured: false` |
| Targets declared but never built | `current.intent.targets` | `configured: false` plus an entry in `not_known` |
| Gate criterion count | `EMBEDDED_WORKFLOW_SPEC_DIR` env → nearest ancestor `workflow-iot/` | `total: null` — never a remembered number |
| Build warning count | not captured | always in `not_known` until a build log is archived |

The last row is intentional. The digest reports what instrumentation is missing rather than pretending the number is zero.

## 7. Known couplings

Two tables in `stage_kernel.py` mirror content owned elsewhere. Both are cited in the output so a reader can verify them against the source.

| Table | Mirrors | Review trigger |
|---|---|---|
| `STAGES` — names, RSMR bars, assumption bars, enforcement defaults | SECTION1 §2 and §4 | Any change to either section |
| *(none for guards)* | The guard list is imported from `tools/guards.py`, so it cannot drift | — |
| `VERSION_NOTES` | ESP-IDF release notes and migration guides | Any IDF major or minor upgrade |

Gate criterion counts are deliberately **not** tabulated — they are parsed from SECTION1 §3 at run time and report `null` when the specification is not reachable.

## 8. Testing without hardware

All of layer 1 is testable against a fixture: a directory with a `CMakeLists.txt` carrying IDF markers, an `sdkconfig`, a `build<target>/project_description.json`, and a `stage-state.yaml`.

Cases that must pass:

```
[ ] non-IDF directory            -> zero lines of output, exit 0
[ ] IDF project, no state file   -> status NO_STATE, bootstrap block present
[ ] normal                       -> status OK, criteria.total parsed from SECTION1
[ ] stage/log mismatch           -> status INCONSISTENT, stage.id null, platform block intact
[ ] unknown schema_version       -> status UNKNOWN_SCHEMA, stage.id null
[ ] agent-adversary attestation with no dossier or undisposed objections -> failures listed
[ ] target declared in intent but never built -> configured false, entry in not_known
[ ] every variant parses under yaml.safe_load once comment lines are removed
[ ] non-ASCII survives the PowerShell hook round trip (no U+FFFD)
[ ] mixed naive/aware timestamps and datetime-valued deadlines do not crash
[ ] an injected defect renders KERNEL_ERROR rather than vanishing
```

Direct invocation for debugging:

```
python tools/stage_kernel.py detect -C <project>
python tools/stage_kernel.py check  -C <project>
python tools/stage_kernel.py cache  -C <project>
python tools/stage_kernel.py digest -C <project>
```

## 9. Install

Copy `tools/` and `hooks/` under `~/.claude/`, then register the hook in `~/.claude/settings.json`:

```json
{ "hooks": { "SessionStart": [ { "hooks": [ { "type": "command",
  "command": "powershell -NoProfile -ExecutionPolicy Bypass -File \"%USERPROFILE%\\.claude\\hooks\\session_start_digest.ps1\"" } ] } ] } }
```

The hook performs its own ESP-IDF detection in PowerShell before starting Python, so an unrelated project costs one directory probe.

**Interpreter.** The ESP-IDF managed virtualenv (`IDF_PYTHON_ENV_PATH`) is preferred because the component manager depends on PyYAML, so it is guaranteed present. Otherwise the first of `python`, `python3`, `py` on PATH is used; if PyYAML is missing there, the digest degrades to `NO_STATE` carrying both the reason and the fix.
